# OA 技术方案

OA 覆盖组织、人事、考勤、审批和薪资，并向集团系统提供 OAuth2 授权码加 PKCE。IR 只使用审批实例和待办，不参与考勤和工资核算。

## 1. 运行位置

单机和与控制塔同机都是后端 `8086`。Open IR 请求头 `X-Api-Key`，种子键 `oa-open-key`。

## 2. 主链路

```text
流程定义 → 发起实例 → 待办 → 同意/驳回/转办
条件分支和多人审批在流程引擎内完成
```

通用流程 `GENERAL` 的登录发起口不允许携带业务单号。控制塔因此不把 `OA_START_WORKFLOW` 打到该登录口。

## 3. 控制塔读

`GET /api/open/ir/snapshots`：

| dataType | 业务键 | 内容 |
| --- | --- | --- |
| `WF_INSTANCE` | 流程实例 | 状态、标题 |
| `WF_TASK` | 待办 id | 待审批任务 |

## 4. 控制塔写

必须带 API Key。

| 指令 | 专用口 | 作用 |
| --- | --- | --- |
| `OA_START_WORKFLOW` | `POST /api/open/ir/start-workflow` | 按流程编码发起。默认可落 `GENERAL`，业务类型 `IR`，业务单号用 `targetKey` |
| `OA_APPROVE_TASK` / `OA_COMPLETE_TASK` | `/approve-task` | 按待办 id 以该待办的审批人同意 |

统一口是 `POST /api/open/ir/actions`。非空幂等键按 `type|业务键|key` 缓存。

## 5. 边界

系统审批写的是流程待办，不是业务系统里的采购订单或开票申请。那些单据要由 SAP、SRM、INV 自己的指令推进。OA 登录发起口与 Open IR 发起口的业务单号规则不同，不要混用。
