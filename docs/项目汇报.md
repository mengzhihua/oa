## 1. 项目背景与定位

集团内部已有 SAP、SRM、CRM、WMS 等业务系统，但缺少一套统一的人事、考勤、薪酬与审批平台，员工需要在多个系统间重复登录，人事口径与工资核算依赖线下表格。

本项目目标是建设一套**行业标准的集团 OA 协同办公平台**：

- 技术约束：后端 Java 8，前端 Vue，与集团既有技术栈一致、便于运维接管；
- 能力对标：用友、金蝶、泛微等主流 OA/HR 产品的核心模块；
- 集团定位：作为集团**统一身份源**（OAuth2.0 授权服务器）与**审批中枢**（向控制塔开放 Open IR 接口）。

## 3. 总体技术架构

![总体架构](images/report/architecture.svg)

*图 2：四层架构——接入层 / 前端层 / 后端层 / 数据运行层*

- **前端**：Vue 3 + Element Plus + Vite + Vue Router + Axios，中文企业级布局（侧边菜单按角色动态生成）。
- **后端**：Java 8 + Spring Boot 2.7.18 + MyBatis-Plus 3.5.3.1 + Spring JDBC，按业务域分包：`system` / `hr` / `attendance` / `workflow` / `payroll` / `collab` / `oauth` / `open`。
- **统一入口**：`AuthInterceptor` 完成 Token 校验，并调用 `UserAccessService.isActive` 统一判断账号有效性（启用状态 + 员工在职状态），再进入 RBAC 权限校验与操作日志。
- **数据层**：默认 H2 文件库开箱即用；提供 MySQL profile 与 Docker Compose；`schema.sql` 47 张表；定时任务处理预定离职到期停用。
- **交付**：GitHub Actions 跨平台打包（Linux / macOS Intel / macOS ARM / Windows / 便携包）。

## 5. 核心业务闭环

![业务闭环](images/report/business-flow.svg)

*图 3：人事 → 考勤 → 审批 → 工资 业务闭环*

关键约束：

1. **入职即开户**：新建员工自动生成 OA 账号，离职到期由调度任务停用账号并将状态置为 `LEFT`。
2. **考勤先锁定再算薪**：月度汇总 `LOCKED` 后工资期间才允许计算，避免算薪后考勤仍被修改。
3. **审批驱动业务**：请假/加班/出差/补卡通过流程引擎审批，审批通过后回调业务（余额扣减、考勤生效）。
4. **工资状态机**：`OPEN → CALCULATED → APPROVED → PAID → CLOSED`，员工仅在 `PAID` 后可见工资条。

## 7. OAuth2.0 统一认证与账号生命周期

![OAuth 时序](images/report/oauth-sequence.svg)

*图 4：授权码 + PKCE 单点登录时序*

**端点**：`/api/oauth/authorize`、`/token`、`/userinfo`、`/introspect`、`/revoke`、`/clients`。

**授权类型**：授权码 + PKCE（浏览器端业务系统）、密码（受信内部系统）、刷新令牌、客户端凭据（服务间调用，不绑定用户）。预置 SAP / SRM / CRM 客户端。

**账号生命周期与认证联动**（PR #13 ~ #26 逐步收敛）：

| 场景 | 行为 |
| --- | --- |
| 员工即时离职 | 账号立即停用；恢复在职则账号恢复 |
| 预定离职（`LEAVING` + `leave_date`） | 到期前可正常使用；到期后调度任务停用账号并置 `LEFT` |
| 到期未跑调度 | 普通登录、密码授权、授权码兑换、刷新令牌均由 `UserAccessService.isActive` 实时拦截 |
| 停用账号尝试兑换/刷新 | 先校验再变更凭据状态，失败不作废原凭据，账号恢复后原凭据仍可用 |
| 兑换过程中账号被停用 | `/token` 授予流程在单事务内执行，签发失败整体回滚 |
| 客户端凭据 | 不关联用户，不受用户有效性校验影响 |

## 8. 控制塔 Open IR 对接

OA 向集团控制塔开放最小接口集，仅涉及**审批实例与待办**，不参与考勤和工资核算：

| 方向 | 接口 | 说明 |
| --- | --- | --- |
| 读 | `GET /api/open/ir/snapshots` | `WF_INSTANCE`（状态、标题）、`WF_TASK`（待审批任务） |
| 写 | `POST /api/open/ir/start-workflow` | 按流程编码发起，默认 `GENERAL`，业务类型 `IR` |
| 写 | `POST /api/open/ir/approve-task` | 以待办审批人身份同意 |
| 写 | `POST /api/open/ir/actions` | 统一指令口，`type|业务键|key` 幂等缓存 |

鉴权采用请求头 `X-Api-Key`。边界：OA 审批写的是流程待办，业务单据由 SAP / SRM / INV 自身推进。详见 [技术方案](技术方案.md)。

## 9. 安全与权限设计

- **认证**：登录 Token 与 OAuth Token 分离；密码与客户端密钥均哈希存储（`PasswordHasher`）。
- **授权**：RBAC 用户-角色-菜单/权限；数据范围控制（普通员工仅可读自身档案/工资条，主管仅读本部门且隐藏写操作）。
- **账号有效性**：`UserAccessService` 单点判定，登录、拦截器、全部 OAuth 用户类授予共用。
- **一致性**：授权码 `used`、刷新令牌 `revoked` 与新令牌签发同事务；跨客户端 revoke。
- **审计**：操作日志记录用户、动作、参数与结果。
- **业务约束**：考勤未锁定禁止算薪、工资状态机单向推进、会议室冲突校验、通用流程登录口禁止携带业务单号。

## 13. 部署与演示方式

- **源码运行**：后端 `mvn spring-boot:run`（8086），前端 `npm run dev`（5176）。
- **发布包**：GitHub Actions 产出各平台原生包与便携包，解压执行 `release-start.*` 即可启动，内置 H2 免安装数据库。
- **生产部署**：切换 MySQL profile，或使用 Docker Compose 一键拉起。
- **演示账号**（仅本地演示）：`admin` 系统管理员、`hr` 人事、`finance` 财务、`manager` 部门主管、`zhangsan` 普通员工。
- **演示脚本**：`scripts/smoke.sh` 可一键生成审批、考勤、工资、公告、会议等演示数据。
